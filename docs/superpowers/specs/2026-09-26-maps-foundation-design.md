# Maps Foundation, Tree Hitboxes and Club Field Rework — Design

Date: 2026-09-26. Branch: `feat/maps-foundation` (from `main` @ f6099c5).

## Context and roadmap

This is cycle ① of the maps update. Each cycle gets its own spec, plan and merge:

1. **Foundation** (this spec): a shared map model, exact obstacle collision, and a detailed club field.
2. **Mountain**: real relief, valley, lake, fir forest, alpine strip; slope soaring to be discussed.
3. **Beach**: coast, animated water, hard-sand strip, dunes, cliff, pier, lighthouse; water impact.
4. **City**: blocks of buildings, streets, lamp posts, power lines, a park with a strip, an abandoned site for FPV.

The visual approach, chosen for all cycles, is **hybrid**: geometry generated by code, plus a small set of CC0 PBR
textures (ambientCG / Poly Haven, 1K). The disk is nearly full (3.4 GB free), so texture budgets are explicit.

## Goals

- Fix the tree hitbox: today a tree collides as a cylinder of radius `0.25 · height` over its whole height, while it
  is drawn as a thin trunk under a cone. For a 16 m tree the hitbox is 4 m wide at the trunk (drawn 0.25 m) and at the
  tip (drawn 0 m), so the aircraft "hits" trees it visibly misses.
- Make render and collision come from **one description**, so they can never diverge again.
- Introduce a map model that the mountain, beach and city maps plug into without touching the flight code.
- Detect thin obstacles (poles, wires) that could pass between the aircraft's hull probe points.
- Make the club field richer: textured ground, varied trees, farmland, road, power line, club buildings.
- Wire the existing « Terrain » menu chips to the chosen map.

## 1. Collision — `SimLab.Flight.Terrain`

### 1.1 Shapes

All shapes are in world ENU (x east, y north, z up). Each implements:

```csharp
public interface IObstacleShape
{
    bool Contains(Vec3 p);
    bool Intersects(Vec3 a, Vec3 b);          // segment a→b
    (double MinX, double MinY, double MaxX, double MaxY) Footprint { get; }  // for the spatial grid
}
```

| Shape | Parameters | Used for | `Intersects` |
|---|---|---|---|
| `VerticalCylinder` | base centre, radius, height | trunks, poles | exact (segment vs capped cylinder) |
| `VerticalCone` | base centre, base radius, height | conifer crowns | sampled |
| `Ellipsoid` | centre, horizontal radius, vertical radius | broadleaf and poplar crowns, bushes | sampled |
| `OrientedBox` | centre, half extents, yaw | hedges, buildings, cars, tables | exact (slab test in box frame) |
| `Capsule` | segment end points, radius | wires | exact (segment–segment distance) |

"Sampled" means points along the segment every ≤ 0.10 m are tested with `Contains`. Sampled shapes are the large
ones (crowns, bushes), where 10 cm is far below their size.

`CylinderObstacle` is replaced by these shapes.

### 1.2 Obstacles and the spatial grid

```csharp
public enum ObstacleKind { Tree, Structure, Wire }
public readonly record struct Obstacle(IObstacleShape Shape, ObstacleKind Kind);

public sealed class ObstacleGrid        // 2D uniform grid, 32 m cells
{
    public ObstacleGrid(IEnumerable<Obstacle> obstacles);
    public ObstacleKind? Hit(Vec3 p);
    public ObstacleKind? Hit(Vec3 a, Vec3 b);
    public IReadOnlyList<Obstacle> All { get; }
}
```

An obstacle is registered in every cell its footprint touches. A query visits only the cells the point or segment
covers, and checks each candidate once.

### 1.3 `ITerrain` and crash detection

`ITerrain.HitsObstacle(Vec3)` becomes:

```csharp
ObstacleKind? HitObstacle(Vec3 p);
ObstacleKind? HitObstacle(Vec3 a, Vec3 b);
```

`FlatTerrain` returns `null` for both.

`GroundContactModel.DetectCrash` checks, for each step:
1. the wheel and hull probe points exactly as today (hard landing, wingtip, nose, hull, belly);
2. each hull point against obstacles, via `HitObstacle(point)`;
3. **every pair of hull points** as a segment, via `HitObstacle(a, b)`. With 7 hull points this is 21 segments. They
   span the aircraft's convex outline, so a pole or wire between the nose and a wingtip is caught.

The first obstacle hit sets the cause:

| `ObstacleKind` | `CrashCause` | FR | EN |
|---|---|---|---|
| `Tree` | `TreeStrike` (existing) | Dans les arbres | Into the trees |
| `Structure` | `StructureStrike` (new) | Contre un obstacle | Hit a structure |
| `Wire` | `WireStrike` (new) | Dans les câbles | Into the wires |

**Tunnelling bound:** crash detection runs at 500 Hz, so at 100 m/s the aircraft moves 0.20 m per step. Wires
therefore collide with a radius of at least **0.10 m** (0.20 m diameter), even though they are drawn thinner. Every
other obstacle is thicker than 0.20 m.

## 2. Map model — `SimLab.App.Maps`

### 2.1 `IFieldMap`

```csharp
public interface IFieldMap
{
    string Id { get; }
    string NameKey { get; }
    MapTerrain Terrain { get; }                 // implements ITerrain: height, normal, obstacles
    MapLayout Layout { get; }
    MapAmbience Ambience { get; }
    IReadOnlyList<Prop> Props { get; }          // everything drawn on top of the terrain
    SurfaceWeights Surface(double x, double y); // ground material mix at a point
    double HalfSize { get; }                    // the terrain covers [−HalfSize, HalfSize]²
}
```

Maps are built deterministically from a fixed seed. Building a map is pure .NET and fully unit-testable.

`MapTerrain` implements `ITerrain`. It combines a height function supplied by the map with an `ObstacleGrid` built from
the props' collision shapes. The normal is computed by central differences, as today.

### 2.2 `MapLayout`

```csharp
public sealed record MapLayout(
    Vec3 PilotPosition, double EyeHeight, Vec3 WindsockPosition,
    Vec3 RunwayCentre, double RunwayLength, double RunwayWidth, double RunwayHeadingDeg);
```

The methods now in `ClubField` move here and are generalised to any runway heading:

- `OnRunway(x, y)`
- `TakeoffHeading(windFromDeg)`: whichever runway direction points most directly into the wind
- `TakeoffPoint(headingDeg)`: 8 m inside the downwind threshold
- `HandLaunchPoint(windFromDeg)`: 3 m from the pilot toward the runway centre line, with the takeoff heading (for
  the club this is 3 m north of the pilot, as today)

### 2.3 `MapAmbience`

Sky top and horizon colours, ground-horizon colours, fog density, and an ambience sound id. The club keeps today's
values and today's birds and wind loop.

### 2.4 Props — one source for render and collision

```csharp
public abstract record Prop(Vec3 Base, double YawDeg)
{
    public abstract IEnumerable<Obstacle> Collision { get; }
}
```

Every prop type defines its **visible dimensions**. The game draws from those dimensions, and `Collision` derives
the hitbox from them. There is no separate hitbox number anywhere else.

| Prop | Visible parameters | Collision |
|---|---|---|
| `BroadleafTree` | height, crown radius, tint | trunk cylinder (exact) + crown ellipsoid at **85 %** of the drawn envelope |
| `PoplarTree` | height, crown radius, tint | trunk cylinder + narrow tall ellipsoid at 85 % |
| `ConiferTree` | height, base radius, tint | trunk cylinder + cone at 85 % of the drawn base radius and full height |
| `Bush` / `Hedge` | size | ellipsoid / oriented box at 85 % |
| `Building` (hangar, shelter) | size, roof type | oriented box (exact) |
| `Car` | size, colour | oriented box (exact) |
| `Table` | size | oriented box (exact) |
| `PowerLine` | pole positions, pole height, sag | pole cylinders + 4 capsules per span following the sag, radius 0.10 m |

The 85 % rule means brushing the outer foliage survives, while the trunk and the heart of the crown are always a
crash (the user's choice). The trunk is exact because it is solid and easy to see.

### 2.5 Surfaces

```csharp
public enum SurfaceKind { Grass, MowedGrass, Dirt, Gravel, Wheat, Ploughed }
public readonly record struct SurfaceWeights(...);   // one weight per kind, summing to 1
```

The ground mesh stores these weights per vertex. The runway, pilot box and paths may also be drawn as flat overlays,
as the runway is today.

### 2.6 Catalog

`FieldCatalog.All` lists `(Id, NameKey, Func<IFieldMap> Create)`, and each map is cached after its first build.
`AppSettings.LastField` still stores the id. An unknown id falls back to the club, as today.

## 3. Club map — `SimLab.App.Maps.Club.ClubMap`

`ClubField`, `ClubFieldTerrain` and `TreePlanter` are replaced by `ClubMap`.

### 3.1 Kept exactly

- The relief formula: flat within 300 m, hills up to 8 m beyond, blended over 300 m.
- The runway: 100 × 15 m, east–west, centred on the origin.
- The pilot at (0, −25), eye height 1.7 m. The windsock at (20, −28). The terrain half size of 1000 m.
- The keep-out zone around the runway and the pilot box: |x| < 110 and |y| < 60. No prop is placed there, except the
  club's own furniture described below.
- Seed 7 for vegetation. The individual tree positions will still differ, since species and new features change the
  generation.

### 3.2 Ground

- Tall grass everywhere by default.
- The runway in mowed grass with alternating 5 m mowing stripes and marked thresholds.
- A gravel pits area around the pilot box.
- A dirt access track from the club south to a small road running east–west at about y = −220.
- Farmland parcels beyond about 350 m: wheat, ploughed fields and meadow, as rotated rectangles 80–200 m across,
  bordered by hedges.
- Large-scale tint variation (noise over 50–200 m), so repeated textures do not tile visibly.

### 3.3 Vegetation

| Species | Look | Where |
|---|---|---|
| Broadleaf (oak) | trunk + a cluster of 3–5 spheres | groves, isolated field trees, the existing tree lines to the north, east and west |
| Poplar | tall and narrow, 18–25 m | a row along the road; a height cue |
| Conifer | stacked cones, 10–20 m | groves far away |
| Bushes and hedges | low, 1–3 m | parcel borders, near the club |

Each tree has a random height, rotation and tint within its species' range. Target: 1500–3000 trees.

### 3.4 Club furniture and structures

- A hangar or shipping container and a shade shelter with picnic tables, west of the pilot box.
- Pit tables along the fence.
- 3 or 4 parked cars on the gravel near the track.
- The existing fence, extended.
- A power line along the road: poles 9 m tall, 50 m spans, 1.5 m sag.

All are collidable.

## 4. Rendering — `game/Scripts/World`

- **`MapBuilder`** replaces `FieldBuilder`. It builds the environment and sun (reusing `AimSun`), the terrain mesh,
  the overlays, the props and the windsock, all from an `IFieldMap`.
- **Terrain mesh:** 5 m grid, indexed, with vertex normals from the terrain. Surface weights go in `COLOR` and
  `CUSTOM0`.
- **Terrain shader:** a `ShaderMaterial` blends the surface textures by those weights. It uses world-space UVs and a
  macro tint noise.
- **`PropMeshes`:** procedural meshes per prop type, built once. Each prop type gets one `MultiMeshInstance3D`,
  plus a simplified far version using visibility ranges (LOD). Only props within about 300 m cast shadows.
- **Textures:** `game/Textures/terrain/` holds grass, dirt, gravel and ploughed ground (albedo, normal and roughness,
  1K JPG). Mowed grass and wheat are tinted variants of grass. Budget: **≤ 30 MB**, with `CREDITS.md` as for the
  audio. The files are downloaded from ambientCG / Poly Haven; the user is asked before any download.

## 5. Integration

- `FlightSession(AircraftDefinition, FlightConditions, IFieldMap)`. `Terrain` is exposed as `ITerrain`, and `Map`
  as `IFieldMap`. `TreeSeed` moves into `ClubMap`.
- These read `session.Map.Layout` instead of `ClubField`: `FlightScene` (ground camera eye, OSD home), `Main`
  (screenshot modes) and `MapBuilder`.
- `MenuAircraftView` shows the selected map and rebuilds it when the « Terrain » chip changes.
- A new option, `--field <id>`, selects the map for the smoke and screenshot modes. It is documented in
  `docs/dev-setup.md`.
- `CrashCause` gains `StructureStrike` and `WireStrike`, with `CRASH_STRUCTURESTRIKE` and `CRASH_WIRESTRIKE` in
  `strings.csv`.
- `docs/realism-backlog.md` gains an entry for rolling friction by surface kind (grass, gravel, asphalt).

## 6. Tests

**Shapes and grid** (`SimLab.Flight.Tests`)
- For each shape, `Contains` and `Intersects` on inside, outside, boundary and tangent cases.
- A segment crossing a thin cylinder or a capsule is detected, although neither end point is inside.
- `ObstacleGrid` gives the same result as a brute-force scan over random points and segments. An obstacle spanning
  several cells is reported once.

**Crash detection**
- Existing `GroundContactTests` still pass, with `TreeStrike` via points.
- An aircraft state whose nose and wingtip straddle a pole, with no hull point inside it, gives `StructureStrike`.
- An aircraft flying through a wire at 100 m/s is detected within one step: no tunnelling.

**Hitbox matches visuals** (`SimLab.App.Tests`)
- For each tree species, a point in the trunk and a point in the heart of the crown hit.
- A point 1 m beside the trunk below the crown, a point above the tip, and a point in the outer 15 % of the drawn
  crown do not hit.

**Club map**
- Same seed gives the same map.
- No prop in the keep-out zone except club furniture, and none on the runway.
- Every prop stands on the terrain: base z equals the terrain height.
- Flat around the runway, hilly far away, normals are unit and upward.
- `MapLayout`: takeoff into the wind for both runway directions, the takeoff point on the runway, and the hand launch
  in front of the pilot.
- `SurfaceWeights` sum to 1 everywhere.
- The tree count is within 1500–3000.

**Session and catalog**
- `FlightSession` with the club map spawns on the runway, as today.
- An unknown field id falls back to the club.

**Game**
- `--smoke-boot` and `--smoke-flight` pass.
- `--screenshot-field` and `--screenshot-flight` produce images of the new club, which are reviewed visually.

**Acceptance by the user**
- Fly the club at ≥ 60 fps (F3 overlay) on their Mac.
- Tree contacts feel fair.
- The menu chips switch the map.

All existing tests stay green (541 plus 1 known skip).

## Out of scope

- The mountain, beach and city maps: cycles ②–④.
- Water and water impact: beach cycle.
- Slope lift from the wind following the relief: to be discussed in the mountain cycle.
- Foliage that slows the aircraft without crashing it.
- Rolling friction by surface: backlog.
- A map editor, or maps as data files.
